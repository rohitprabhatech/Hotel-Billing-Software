# 02 — Functional Requirements

## FR-1 Multi-Tenancy

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-1.1 | Every hotel is a tenant with a unique `tenant_id` (UUID) | Must |
| FR-1.2 | Tenant-scoped tables include `tenant_id` | Must |
| FR-1.3 | Backend derives `tenant_id` from JWT; never trusts client-supplied tenant | Must |
| FR-1.4 | All queries filter by authenticated tenant | Must |
| FR-1.5 | Cross-tenant read/write/export is forbidden | Must |

## FR-2 Authentication & Users

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-2.1 | Login via email + password returns JWT | Must |
| FR-2.2 | Only roles: `OWNER`, `BILLING_USER` | Must |
| FR-2.3 | Passwords stored as secure hashes (never plaintext) | Must |
| FR-2.4 | Owner can create/manage Billing Users for their tenant | Must |
| FR-2.5 | Users can be deactivated (soft disable), not hard-deleted for history | Must |
| FR-2.6 | Login/logout recorded in audit log | Must |

## FR-3 Categories

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-3.1 | Owner can create, update, activate/deactivate categories | Must |
| FR-3.2 | Categories are tenant-specific and not hard-coded | Must |
| FR-3.3 | Optional parent category for subcategory hierarchy | Should |
| FR-3.4 | Billing User can list active categories for billing UX | Must |

## FR-4 Items

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-4.1 | Owner CRUD for items: name, category, description, price, GST %, status | Must |
| FR-4.2 | Price and GST changes are audited | Must |
| FR-4.3 | Deactivate instead of delete; inactive items hidden from new bills | Must |
| FR-4.4 | Search and filter items | Must |
| FR-4.5 | Historical bills retain item name/price/GST snapshots | Must |

## FR-5 Billing

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-5.1 | Billing User creates bills: search, add, qty change, remove, clear draft | Must |
| FR-5.2 | Permitted discount application before finalize | Must |
| FR-5.3 | Backend recalculates subtotal, discount, taxable, CGST, SGST, grand total | Must |
| FR-5.4 | Bill number generated by backend; unique per tenant under concurrency | Must |
| FR-5.5 | Bill finalize is atomic (bill + items + audit) | Must |
| FR-5.6 | After finalize, silent edits are not allowed | Must |
| FR-5.7 | Cancel/void requires reason; status change only (no hard delete) | Must |
| FR-5.8 | Billing User cannot hard-delete bills or bill items | Must |
| FR-5.9 | Optional table number / order reference fields if configured | Should |

## FR-6 Bill Printing

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-6.1 | Dedicated printable receipt component (thermal 58mm/80mm where practical) | Must |
| FR-6.2 | Dynamic hotel header: name, address, city/pincode, phone, GSTIN, FSSAI | Must |
| FR-6.3 | Line items: particulars, qty, rate, amount; GST breakdown; totals | Must |
| FR-6.4 | Print and reprint actions audited | Must |
| FR-6.5 | Print view hides app chrome; prints receipt only | Must |

## FR-7 Owner Dashboard & Reports

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-7.1 | Cards: Today's Sales, Bills, Discount, GST, Average Bill, Items Sold, Cancelled Bills | Must |
| FR-7.2 | Periods: Today, Yesterday, This Week, This Month, Last Month, Custom Range | Must |
| FR-7.3 | Period comparison (e.g., today vs yesterday, this month vs last month) | Must |
| FR-7.4 | Item-wise and day-wise sales for monthly/custom reports | Must |
| FR-7.5 | Export Excel, CSV, and PDF where appropriate; tenant-scoped filenames | Must |

## FR-8 Billing User Dashboard

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-8.1 | Simple dashboard: New Bill, Today's Bills, Today's Total, Recent Bills | Must |
| FR-8.2 | Billing screen is primary UX; no owner analytics overload | Must |
| FR-8.3 | View own/relevant bill history and reprint if permitted | Must |

## FR-9 Audit & Fraud Monitoring

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-9.1 | Audit log fields: tenant, user, action, entity, old/new data, IP, UA, timestamp | Must |
| FR-9.2 | Actions include login, item CRUD, bill create/cancel/print/reprint, price/GST, exports | Must |
| FR-9.3 | Owner-only Activity & Audit Dashboard with filters | Must |
| FR-9.4 | Detail view for each audit event (e.g., cancel reason, amounts) | Must |
| FR-9.5 | Activity alerts: high cancellations, unusual discounts, reprints, price changes | Should |
| FR-9.6 | Audit logs are not deletable via application | Must |

## FR-10 Tenant Profile

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-10.1 | Owner can view/update hotel business profile used on receipts | Must |
| FR-10.2 | GSTIN, FSSAI, address, phone stored per tenant | Must |

## FR-11 Validation & Errors

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-11.1 | Request validation with clear error messages | Must |
| FR-11.2 | Consistent API error envelope; no stack traces to clients | Must |
| FR-11.3 | Confirmation dialogs for destructive/irreversible business actions (cancel, deactivate) | Must |
